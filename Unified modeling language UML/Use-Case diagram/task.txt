Имеется краткое текстовое описание функций информационной системы. Проанализируйте это описание и создайте диаграмму вариантов использования. Обратите внимание, что начальном этапе разработки любой системы такие диаграммы создаются для продвижения разработки самой системы и не являются ее техническим описанием. Основная цель — донести до слушателей (как правило, непрограммистов) возможности разрабатываемой системы.

Требуется разработать систему для абонемента библиотеки. Библиотека зарабатывает деньги, выдавая напрокат некоторые книги, имеющиеся в небольшом количестве экземпляров. Система должна отслеживать финансовые показатели работы библиотеки.

У каждой выдаваемой в прокат книги есть название, автор, жанр. В зависимости от ценности книги определена для каждой из них залоговая стоимость (сумма, вносимая клиентом при взятии книги напрокат) и стоимость проката (сумма, которую клиент платит при возврате книги, получая назад залог). Стоимость проката книги зависит не только от самой книги, но и от срока ее проката.

В библиотеку обращаются читатели. Все читатели регистрируются в картотеке, которая содержит стандартные анкетные данные (ФИО, адрес, телефон, категория). Каждый читатель может обращаться в библиотеку несколько раз. Все обращения читателей фиксируются, при этом по каждому факту выдачи книги (при наличии экземпляра) фиксируется дата выдачи и ожидаемая дата возврата.

Кроме того, в системе должна быть реализована система штрафов за нанесенный книге вред и система скидок для некоторых категорий читателей. Также в системе должно быть реализовано отслеживание заказов читателей (сроков их исполнения и возврата книг), информирование читателей о новых поступлениях и просроченных книгах.

Нарисуйте диаграмму вариантов использования
Запустите предпочтительную среду для рисования диаграмм.
Создайте новую диаграмму вариантов использования (use-case diagram).
Подумайте о том, каких актеров можно создать.
Опишите варианты использования для каждого из актеров.
Подумайте можно ли использовать генерализацию (наследования) для актеров (в этом случае обычно 2 и более актеров ассоциированы с одним и тем же вариантом использования).
Подумайте есть ли варианты использования, которые имеют общие действия (вынесите такие действия через отношение включения (include)).
Подумайте есть ли варианты использования, которые имеют суб-действия выполняемые не всегда (вынесите такие действия в отношение расширения (extend)).
Вернитесь к шагу 3 (если удалось что-нибудь изменить с момента последней итерации).
Примечание. Главное в каждом варианте использования — значимый результат. Помните, что актер должен ясно понимать какой результат работы он получит в рамках каждого варианта использования.

Примечание. Диаграмма вариантов использования не показывает порядок действий, архитектурные вещи и др. Она показывает только варианты использования разрабатываемого приложения.
